# Wiki 스키마 — 관리 규칙

> 이 파일은 LLM이 wiki를 어떻게 읽고 쓰고 유지하는지 정의한다.

---

## 3계층 구조

```
[원본 소스] → 읽기 전용. SKILL.md, 실제 데이터, 사용자 입력
     ↓ ingest
[wiki/] → LLM이 생성·유지하는 마크다운 페이지
     ↓ query
[사용자 질의 응답]
```

원본 소스는 절대 수정하지 않는다. wiki만 수정한다.

---

## 페이지 작성 규칙

### 파일명
- 소문자 + 하이픈: `qa-framework.md`
- 단일 개념 하나당 파일 하나

### 헤더 구조
```markdown
# [페이지 제목]

> [한 줄 요약 — 이 페이지가 무엇을 다루는가]

**최종 수정:** YYYY-MM-DD  
**관련 페이지:** [[링크1]] · [[링크2]]  
**소스:** [어떤 SKILL/데이터에서 왔는가]
```

### 링크 컨벤션
- 다른 wiki 페이지 참조: `[qa-framework](qa-framework.md)`
- 원본 소스 참조: `[qa-scoring SKILL](../cs-quality-analysis/skills/qa-scoring/SKILL.md)`

### 금지 사항
- 개인정보(상담사 실명, 고객 정보) 직접 기재 금지
- 확인되지 않은 수치를 기정사실로 기재 금지 — `[미확인]` 태그 사용

---

## 4가지 핵심 작업

### 1. Ingest (새 지식 추가) — 2단계 CoT

nashsu/llm_wiki 패턴 적용. 한 번에 쓰지 않고 반드시 분석 → 생성 순서로 진행한다.

**1단계: 분석 (쓰기 전)**
```
다음 질문에 먼저 답한다 (내부 추론, 출력 불필요):
1. 이 소스의 핵심 개념은 무엇인가? (3-5개)
2. 기존 wiki 페이지 중 업데이트가 필요한 것은?
3. 새로 만들어야 할 페이지가 있는가?
4. 기존 내용과 모순되는 항목이 있는가?
5. [미확인] 태그가 필요한 수치나 주장이 있는가?
```

**2단계: 생성 (분석 결과 반영)**
```
분석 결과를 바탕으로:
- 관련 기존 페이지 업데이트 (최종 수정 날짜 갱신)
- 필요한 신규 페이지 생성
- 모순 발견 시 해당 페이지에 ⚠️ 충돌 태그 추가
- index.md 업데이트
- log.md에 소스명 + 변경 내용 기록
```

**캐싱 원칙:** 이미 인제스트한 소스는 log.md에서 확인 후 재처리 생략.

---

### 2. Query (질문 응답)
관련 wiki 페이지 검색 → 답변 생성 → 좋은 답변은 새 페이지로 추가

---

### 3. Lint (정기 점검)

`/wiki-lint` 커맨드로 실행. 점검 항목:

| 항목 | 감지 방법 | 심각도 |
|------|-----------|--------|
| 고아 페이지 | index.md 목록에 없는 wiki/*.md 파일 | 🔴 HIGH |
| 끊긴 링크 | `(*.md)` 링크 대상 파일 존재 여부 | 🔴 HIGH |
| ⚠️ 충돌 태그 미해결 | 페이지 내 `⚠️ 충돌` 텍스트 검색 | 🔴 HIGH |
| `[미확인]` 태그 누적 | 페이지 내 `[미확인]` 텍스트 검색 | 🟡 MEDIUM |
| 오래된 페이지 | 최종 수정 날짜 90일 초과 | 🟡 MEDIUM |
| 링크 없는 고립 페이지 | 다른 페이지에서 참조되지 않는 페이지 | 🟢 LOW |

결과는 lint 리포트 형식으로 출력 후 log.md에 기록.

---

### 4. Update (수정)
기존 페이지 수정 시 → `최종 수정` 날짜 업데이트 → log.md에 변경 이유 기록

---

### 모순 처리 규칙

같은 지표에 다른 기준값이 발견되면:
1. 해당 페이지에 `⚠️ 충돌: [내용]` 추가
2. log.md에 충돌 사실 기록
3. 사용자에게 어느 값이 맞는지 확인 요청
4. 확인 후 올바른 값으로 수정 + `⚠️ 충돌` 태그 제거

---

## 특수 파일

| 파일 | 역할 | 수정 주체 |
|------|------|-----------|
| `index.md` | 전체 카탈로그 | 페이지 추가/삭제 시 자동 업데이트 |
| `log.md` | 변경 이력 | 모든 작업 후 기록 |
| `schema.md` | 이 파일 | 규칙 변경 시만 수정 |
