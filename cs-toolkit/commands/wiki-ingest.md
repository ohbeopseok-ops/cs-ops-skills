# /wiki-ingest — Wiki 새 지식 인제스트

**목적:** 새 소스(SKILL, 데이터, 사례, 문서)를 2단계 CoT로 분석해 wiki에 반영한다.

---

## 사용법

```
/wiki-ingest [소스 내용 또는 파일 경로]
/wiki-ingest ../cs-quality-analysis/skills/qa-scoring/SKILL.md
/wiki-ingest "이번 주 FCR이 45%로 하락했고, 원인은 신규 상담사 배치였음"
/wiki-ingest --list    ← log.md에서 이미 처리한 소스 목록 확인
```

---

## 실행 절차

### 전처리: 중복 확인
`log.md`에서 동일 소스가 이미 인제스트됐는지 확인.  
이미 처리된 소스면 → "이미 인제스트된 소스입니다. 재처리하려면 `--force` 추가" 출력 후 종료.

---

### 1단계: 분석 (쓰기 전 내부 추론)

소스를 읽고 다음 5가지를 파악한다. **이 단계에서는 wiki 파일을 수정하지 않는다.**

```
[분석 체크리스트]

1. 핵심 개념 추출
   → 이 소스에서 wiki 페이지로 만들 가치가 있는 개념 3-5개

2. 기존 페이지 영향도 확인
   → wiki/ 파일 중 업데이트가 필요한 페이지와 수정 내용

3. 신규 페이지 필요 여부
   → 기존 페이지로 커버 안 되는 새 개념이 있는가

4. 모순 탐지
   → 기존 wiki의 수치/기준과 충돌하는 내용이 있는가
   → 있으면: 어느 페이지의 어느 항목과 충돌하는가

5. 불확실성 식별
   → 검증이 필요한 수치, 주장, 날짜 → [미확인] 태그 대상
```

분석 결과를 사용자에게 요약 출력:
```
## 인제스트 분석 결과

**소스:** [소스명]
**핵심 개념:** [개념1] · [개념2] · [개념3]
**업데이트 대상:** [페이지명] (수정 내용 요약)
**신규 페이지:** [있음/없음] — [페이지명]
**모순 감지:** [없음 / 있음 — 상세]
**[미확인] 항목:** [없음 / 있음 — 상세]

계속 진행할까요? (자동 진행 or 확인 후 진행)
```

---

### 2단계: 생성 (분석 결과 반영)

분석 결과를 바탕으로 순서대로 실행:

1. **기존 페이지 업데이트**
   - 내용 수정
   - `최종 수정:` 날짜 오늘로 갱신
   - 모순 있으면 `⚠️ 충돌: [내용]` 추가

2. **신규 페이지 생성** (필요 시)
   - schema.md 헤더 구조 준수
   - 관련 기존 페이지에 상호 링크 추가

3. **index.md 업데이트**
   - 신규 페이지 목록 추가

4. **log.md 기록**

```
## YYYY-MM-DD

**Ingest: [소스명]**
- 업데이트: [페이지1], [페이지2]
- 신규 생성: [페이지명] (없으면 생략)
- 모순 감지: [없음 / 페이지명 — 내용]
- [미확인] 태그: [없음 / 항목 수]
**소스:** [소스 경로 또는 설명]
```

---

## 인제스트 완료 메시지

```
✅ 인제스트 완료

업데이트된 페이지: N개
신규 페이지: N개
⚠️ 충돌 태그: N건 (확인 필요)
[미확인] 태그: N건

충돌 또는 미확인 항목이 있으면 /wiki-lint로 점검 권장
```
