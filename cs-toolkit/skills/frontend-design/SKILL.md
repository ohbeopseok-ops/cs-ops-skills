# Frontend Design — JOYLAB UI 설계 원칙

> 모든 클라이언트에게 똑같은 외관을 제안하지 않는 작은 디자인 스튜디오의 리드로서 행동한다.
> 템플릿 같은 제안은 이미 여러 번 거부당했다.
> 색·타이포·레이아웃·카피 모든 선택에 "왜 이 도구인가"를 설명할 수 있어야 한다.

-----

## ❶ 설계 전 필수 정의

브리프가 모호하면 설계 전에 다음 세 가지를 먼저 확정하고 명시한다:

```
1. 이 도구/페이지는 무엇인가?       → 서비스 정의
2. 누구를 위한 것인가?              → 사용자 정의 (상담사 / 실장 / 고객 / 독자)
3. 이 페이지의 단 하나의 목적은?    → 단일 목적 선언
```

이 세 가지가 없으면 디자인을 시작하지 않는다.
JOYLAB 메모리에 있는 도구 맥락(cs-ops, 블로그, 투자 인포그래픽 등)이 있으면 힌트로 사용한다.

-----

## ❷ JOYLAB 디자인 토큰 (기본값)

|역할        |값                                       |
|----------|----------------------------------------|
|배경        |`#FAFAF7` (크림 화이트)                      |
|잉크        |`#1A1A1A`                               |
|앰버 골드 (강조)|`#C17F24`                               |
|틸 (보조 강조) |`#2D7D6F`                               |
|디스플레이 폰트  |Pretendard (700/900)                    |
|본문 폰트     |Pretendard (400/500)                    |
|데이터/캡션 폰트 |Pretendard (300, letter-spacing +0.02em)|


> 이 토큰은 기본값이다. 브리프가 다른 방향을 명시하면 브리프가 이긴다.
> 단, 변경 시 "왜 이 색인가"를 한 줄로 설명해야 한다.

### 색상 확장 규칙

- 메인 팔레트는 4–6색 이내로 제한
- 추가 색 사용 시 앰버 또는 틸의 명도 변형(10% 단위)을 우선 검토
- 빨강 계열은 오류·경고 전용으로만 사용 (`#D64045`)

## ❸ 디자인 원칙 6가지

### 1. 히어로 섹션은 "주장"이다

- 첫 화면은 이 도구가 무엇을 해결하는지를 단 한 문장으로 선언해야 한다
- "기능 나열"이 아니라 "문제 해결 선언"으로 시작한다
- 큰 숫자 + 작은 레이블 + 그라디언트 강조는 템플릿 답변 → 이 도구에 맞는 형식인지 먼저 질문한다

```
❌ "상담 품질 분석 시스템"
✅ "STT 발화 데이터에서 코칭 포인트를 3초 안에 꺼냅니다"
```

### 2. 타이포그래피에 개성을 부여한다

- 디스플레이 / 본문 / 데이터 세 역할을 구분하고, 각 역할에 명확한 크기·두께·간격을 부여한다
- 타입 자체가 기억에 남는 디자인 요소여야 한다 (투명한 전달 도구가 아니다)
- Pretendard를 사용하되, 자간·행간·크기 비율로 개성을 만든다

### 3. 구조에 의미를 부여한다

- `01 / 02 / 03` 번호 마커는 실제 순서 정보가 있을 때만 사용한다
- 구분선·레이블·아이콘은 콘텐츠의 진실을 인코딩해야 한다 (장식 금지)
- 카드 레이아웃은 항목이 독립적일 때, 리스트는 관계가 있을 때 사용한다

### 4. 애니메이션은 목적을 부여한다

- 페이지 로드 / 스크롤 트리거 / 호버 마이크로인터랙션 — 각각 사용 목적을 먼저 정의한다
- 여러 곳에 흩어진 효과보다 한 곳의 연출이 더 강하다
- 과도한 애니메이션은 "AI가 만든 느낌"을 강화한다 → 절제 우선

### 5. 비전에 따라 복잡성을 선택한다

- 복잡한 방향 → 정교한 실행
- 미니멀 방향 → 여백·타입·디테일의 정밀도
- 어느 쪽이든 "선택한 비전을 잘 실행하는 것"이 우아함이다

### 6. 카피라이팅도 디자인의 일부다

- 사용자 관점에서 쓴다: 시스템 구현이 아니라 사용자가 제어하는 것을 이름짓는다
- 동사를 사용한다: "저장" → "변경사항 저장", "확인" → "분석 시작"
- 오류는 원인과 대처를 함께 쓴다
- 빈 상태는 다음 행동을 제시한다

```
❌ "데이터가 없습니다"
✅ "STT 파일을 업로드하면 분석을 시작합니다 → [파일 선택]"

❌ "오류가 발생했습니다"
✅ "API 연결에 실패했습니다. 네트워크를 확인하거나 잠시 후 다시 시도하세요"
```

## ❹ 작업 프로세스

```
① Brainstorm  — 색·타입·레이아웃·시그니처 요소 아이디어 도출
② Explore     — 방향성 비교 (ASCII 와이어프레임 또는 토큰 대안 2–3개)
③ Plan        — 최종 토큰 시스템 확정 + 레이아웃 설계
④ Critique    — 자체 리뷰 (아래 기준 적용)
⑤ Build       — 계획을 정확히 따라 구현
⑥ Critique Again — 재리뷰 후 완료 선언
```

대부분의 Brainstorm·Explore 과정은 내부 사고에서 처리하고,
사용자에게는 Plan 이후의 결과물만 제시한다.

-----

## ❺ 자체 리뷰 (Critique) 체크리스트

구현 전과 후, 두 번 통과해야 한다.

```
[ ] 이 도구의 서비스 정의·사용자·목적이 디자인에 반영되어 있는가?
[ ] 다른 프로젝트에 그대로 전용할 수 있는 디자인인가? → YES면 재설계
[ ] 색·타입·레이아웃 각 선택에 "이유"를 한 줄로 말할 수 있는가?
[ ] 시그니처 요소(이 페이지를 기억하게 만드는 단 하나)가 있는가?
[ ] 카피가 동사 기반이고 사용자 관점인가?
[ ] 빈 상태·오류 상태가 다음 행동을 안내하는가?
[ ] CSS 선택자 충돌 (padding/margin 중첩, .section vs 요소 선택자)이 없는가?
[ ] 모바일 대응 / 키보드 포커스 / reduced-motion 기본값이 있는가?
[ ] 장식적 요소 중 제거해도 되는 것이 하나라도 있는가? → 제거한다
```

## ❻ JOYLAB 도구 유형별 적용 가이드

### CS 운영 도구 (KPI 대시보드, STT 분석, QA 채점)

- 히어로: "무엇을 분석하는 도구인가"를 상단 한 줄로 선언
- 데이터 시각화는 틸(`#2D7D6F`) 단색 또는 앰버 강조 단계 사용
- 숫자는 크게, 레이블은 작게, 단위는 더 작게 (3단 계층)
- 빈 상태: "데이터를 업로드하면 분석이 시작됩니다" + 업로드 버튼

### 투자·ETF 인포그래픽 (HTML 리포트)

- 히어로: 핵심 수치 1개 + 해석 문장 1줄
- 배경 `#FAFAF7` + 섹션 구분은 `border-top: 1px solid #E8E4DC`
- 앰버(`#C17F24`)는 강조 수치·상승 신호에만 사용
- 차트는 단순하게: 색 3개 이내, 범례는 차트 안에

### 블로그·콘텐츠 컴포넌트

- 카드 UI는 그림자 최소화 (`box-shadow: 0 1px 4px rgba(0,0,0,0.08)`)
- 태그·카테고리는 틸 배경 + 흰 글자 (소문자, Pretendard 500)
- CTA 버튼: "더 보기" → "분석 전체 보기" / "구독" → "주간 ETF 받기"

### 폐쇄망 HTML 도구

- 외부 CDN 없음: Pretendard는 base64 embed 또는 시스템 폰트 fallback
- `font-family: 'Pretendard', -apple-system, 'Apple SD Gothic Neo', sans-serif`
- 인라인 CSS 허용, JS는 vanilla만 사용

## ❼ 금지 패턴 (Generic Default 목록)

아래 패턴은 브리프가 명시하지 않는 한 사용 금지:

|패턴                               |이유       |
|---------------------------------|---------|
|크림 배경 + 세리프 디스플레이 + 테라코타 강조      |AI 기본값 1번|
|검은 배경 + 산성 초록·빨강 단일 강조           |AI 기본값 2번|
|신문 격자 + 헤어라인 룰 + 제로 border-radius|AI 기본값 3번|
|"시작하기" "더 알아보기" 버튼 기본 카피         |의미 없는 동사 |
|`01 / 02 / 03` 마커 (순서 없는 콘텐츠에)   |구조 오남용   |
|카드 4개 나란히 + 아이콘 + 짧은 설명          |기능 나열 템플릿|
