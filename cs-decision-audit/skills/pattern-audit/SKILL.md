# 지식베이스 감사 (Pattern Audit)

노트가 얼마나 쌓였는지가 아니라, 그 안의 판단이 서로 모순되지 않는지·낡지 않았는지·근거가 있는지를 정기적으로 검증하는 점검 루틴.

## 점검 6개 카테고리

1. **모순**: 서로 다른 노트가 같은 주제에 대해 양립할 수 없는 판단을 내리고 있는가.
2. **반복되는 실수**: 시점이 다른 여러 노트에서 같은 유형의 실패 패턴이 되풀이되는가.
3. **폐기 후보**: `valid_until`이 지났거나, 이후 노트에서 이미 뒤집힌 판단인데 `status: active`로 남아 있는가.
4. **출처 없는 주장**: `source_file` / `source_quote`가 비어 있거나 원자료로 추적되지 않는 fact·decision 노트가 있는가.
5. **고립 노트**: 어떤 노트에서도 링크되지 않고, 어떤 노트도 링크하지 않는 노트가 있는가 — 맥락 없이 홀로 존재하는 판단.
6. **미해결 질문**: 노트 안에서 "판단 불가"로 남긴 항목 중, 이후 자료로도 여전히 채워지지 않은 것이 있는가.

## 원칙

- **의견이 아니라 근거로 판정**: "모순으로 보인다"가 아니라 두 노트의 파일명과 인용을 나란히 제시해 사용자가 직접 판단하게 한다.
- **시점 차이와 모순을 혼동하지 않는다**: 노트 A(3월)와 노트 B(7월)가 다른 결론이어도, B가 A를 대체(`superseded_by`)했다면 이는 모순이 아니라 정상적인 판단 변화다. 이 경우 "변화 이력"으로 분류하고 모순 목록에는 넣지 않는다.
- **동명이인·유사 사례 주의**: 이름이나 상황이 비슷하다고 같은 사안으로 단정하지 않는다. 불확실하면 "확인 필요"로 표시한다.
- **기록 부재를 사실 부재로 해석하지 않는다**: 특정 이슈에 대한 노트가 없다는 것이 "그 이슈가 없었다"는 뜻은 아니라고 명시한다.

## 출력 형식

ALWAYS use this exact template:

```markdown
## 지식베이스 감사 리포트 — [점검 범위/날짜]

### 1. 모순
| 노트 A | 노트 B | 충돌 내용 |
|---|---|---|
| [[노트A]] | [[노트B]] | [무엇이 양립 불가능한지] |

### 2. 반복되는 실수
- [패턴 설명] — 관련 노트: [[노트1]], [[노트2]], [[노트3]]

### 3. 폐기 후보
| 노트 | 사유 | 대체 노트 |
|---|---|---|
| [[노트]] | [valid_until 경과 / 이후 판단에 의해 뒤집힘] | [[대체 노트]] 또는 없음 |

### 4. 출처 없는 주장
- [[노트]] — [무엇이 누락됐는지: source_file 없음 / source_quote 없음]

### 5. 고립 노트
- [[노트]] — [주제, 왜 연결이 필요해 보이는지]

### 6. 미해결 질문
- [질문] — 최초 제기: [[노트]] / [며칠째 미해결인지, 확인 가능하면]

### 변화 이력 (모순 아님, 참고용)
- [[구 노트]] → [[신 노트]]: [무엇이 왜 바뀌었는지]

### 종합
[점검 범위 내 판단 품질에 대한 1~2문장 요약. 노트 개수가 아니라 위 6개 카테고리 건수 기준으로 서술.]
```

## 사용 예시

- `상담품질 도메인 노트 전체를 감사해줘`
- `최근 3개월 판단 노트에서 모순되는 것 찾아줘`
- `폐기해야 할 오래된 판단이 있는지 점검해줘`
