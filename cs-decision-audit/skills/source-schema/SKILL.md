# 원자료 구조화 (Source Schema)

원자료를 훼손하지 않으면서 의미 단위로 쪼개고, 나중에 근거를 추적할 수 있도록 메타데이터를 부여하는 규칙.

## 원칙

- **원본 불변**: 원자료(인터뷰 로그, VOC 원문, 회의록 등)는 절대 수정하지 않는다. 노트는 원자료를 "가리키는" 별도 산출물이다.
- **원자 단위 분해**: 하나의 노트는 하나의 주장/관찰/판단만 담는다. "상담사는 예외 상황을 어려워하고, 리더 피드백도 늦다"처럼 두 개 이상의 독립된 주장을 한 노트에 섞지 않는다.
- **문장 단위 출처**: 파일명만으로는 부족하다. 어느 절/구간에서 나온 말인지, 원문 인용까지 남긴다.
- **과잉 분해 금지**: 문맥 없이 이해 불가능할 정도로 잘게 쪼개지 않는다. 노트 제목만 읽고 무슨 내용인지 짐작 가능해야 한다.
- **claim_type 필수 표기**: 사실과 의견을 같은 문장 구조로 적으면 나중에 사실처럼 재사용된다. 아래 5종 중 하나를 반드시 지정한다.

## claim_type 5종

| claim_type | 의미 | 예시 |
|---|---|---|
| fact | 관측·기록된 사실 | "7월 인터뷰 12건 중 8건에서 동일 반응" |
| interpretation | 사실에 대한 해석 | "고객은 비용보다 통제력 상실에 반응하는 것으로 보인다" |
| hypothesis | 아직 검증되지 않은 가설 | "공감 우선 순서가 재문의율을 낮출 것이다" |
| decision | 실제로 내려진 결정 | "8월부터 상담 순서를 공감→이유→기준으로 변경한다" |
| lesson | 사후 검증을 거친 교훈 | "설명을 먼저 하면 반발이 커진다는 것이 반복 확인됨" |

## 노트 메타데이터 스키마

```yaml
---
type: fact | interpretation | hypothesis | decision | lesson
domain: [상담품질 | 코칭 | VOC | 콘텐츠 | 투자 | ...]
created: YYYY-MM-DD
valid_from: YYYY-MM-DD
valid_until: null 또는 YYYY-MM-DD
status: active | superseded | archived
superseded_by: [[대체 노트]] (해당 시)
confidence: high | medium | low
source_file: 원자료 파일명
source_section: 원자료 내 구간 (예: "김OO 인터뷰 > 설치비 상담")
source_quote: "원문 인용 한 문장"
---
```

## 처리 절차

1. 원자료를 통째로 읽는다. 임의로 요약하지 않는다.
2. 독립된 주장/관찰 단위로 후보를 나열한다.
3. 각 후보에 claim_type을 부여한다. 애매하면 hypothesis로 낮춰 잡는다 — 과신보다 과소평가가 안전하다.
4. 위 스키마로 프론트매터를 채우고, 제목은 주장을 한 문장으로 요약해 붙인다.
5. 기존 노트와 명백히 겹치는 주제가 있으면 병합 대신 관련 노트로 링크만 걸어 둔다 (중복 노트는 pattern-audit에서 별도로 잡아낸다).

## 출력 형식

각 원자료에 대해 다음을 제시한다:

```
## 원자료: [파일명]

### 후보 노트 목록
1. [제목] — claim_type: [fact/interpretation/hypothesis/decision/lesson]
   - 출처: [source_section] / "[source_quote]"
2. ...

### 분해 시 주의
- [두 주장이 섞여 있던 부분 등, 있으면만 기재]
```

## 사용 예시

- `이 상담사 인터뷰 로그를 원자적 노트로 쪼개줘: [텍스트]`
- `이번 주 VOC 원문을 구조화해줘`
- `이 투자 판단 메모에서 사실과 해석을 분리해줘`
