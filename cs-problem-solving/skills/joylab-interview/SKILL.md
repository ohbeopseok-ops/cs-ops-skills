# JOYLAB 인터뷰 (JOYLAB Interview)

Intent 분석에서 "미확인"으로 표기된 항목 중 실제로 결과 품질을 좌우하는 것만 골라 묻는다. 사용자에게 프롬프트 엔지니어링을 학습시키지 않는다 — 시스템이 무엇을 모르는지 판단하고 대신 물어본다.

## 질문 규칙

```
1. 이미 원 요청 또는 이전 답변에 있는 내용은 다시 묻지 않는다.
2. 질문은 최대 10개.
3. 한 번에 1~2개씩만 묻는다 (한꺼번에 나열 금지).
4. 정보가 충분하면 남은 질문 없이 즉시 종료한다.
5. 질문 수를 채우는 것이 목표가 아니다 — Information Gain(그 답변이 최종 결과를 얼마나 바꾸는가)이 낮은 질문은 생략한다.
```

## Information Gain 판단 기준

질문을 던지기 전에 자문한다: "이 답변에 따라 최종 실행 계획(Execution/Action)이 달라지는가?"
- 달라진다 → 질문한다
- 달라지지 않는다 (형식적 확인용) → 생략하고 합리적 기본값을 project-spec에 명시한다

## 업무 유형별 핵심 질문 뱅크

Intent 분석의 업무 유형에 따라 우선순위가 높은 질문부터 선택한다. 아래는 시작점이며, 이미 답이 있는 항목은 제외한다.

**품질분석**
- 평가 대상은 개인/팀/전체 중 무엇인가요?
- 평가 기준은 기존 QA 스코어카드를 그대로 쓰나요, 새 기준이 필요한가요?

**코칭**
- 코칭 대상자의 최근 평가 결과나 취약 항목이 있나요?
- 코칭 주기는 1회성인가요, 반복 프로그램인가요?

**성과관리**
- 비교 기준(전월/전분기/팀 평균) 중 무엇을 기준으로 하나요?
- 목표는 이미 정해져 있나요, 이번에 함께 설정하나요?

**VOC**
- 분석 대상 기간과 채널(콜/채팅/게시판)은 어디까지인가요?
- 원인 분석까지 필요한가요, 분류만 필요한가요?

**운영기획**
- 결과물을 누구에게 보고하나요 (실무선/팀장/경영진)?
- 실행 시점은 언제까지인가요?

**리포팅**
- 보고 주기와 대상 독자는 누구인가요?
- 반드시 포함해야 할 지표가 있나요?

## 진행 형식

ALWAYS follow this pattern:

```
## Interview — [n/10]

[질문 1]
[질문 2 (있는 경우, 최대 2개)]

→ 답변 주시면 계속 진행하거나, "충분해요"라고 말씀하시면 바로 project-spec으로 넘어갑니다.
```

정보가 충분하다고 판단되면 질문 대신 아래로 종료한다.

```
## Interview 종료 — 정보 충분

수집된 정보만으로 project-spec 작성이 가능합니다. 바로 진행할까요?
```

## 사용 예시

- (intent-classify 직후) `이제 필요한 정보만 1~2개씩 물어봐줘`
- `질문 그만하고 지금까지 답변으로 바로 스펙 만들어줘` → 즉시 종료 처리
