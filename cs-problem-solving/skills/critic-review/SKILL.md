# 실행 결과 비판적 검토 (Critic Review)

첫 실행 결과를 만든 것과 같은 관점으로 검토하지 않는다. 별도의 검증자 관점에서 결과를 깨뜨려본다.

## 검증 영역

```
Fact         결과에 사실 오류나 근거 없는 단정이 있는가
Logic        원인→결론 사이에 논리 비약이 있는가
Assumption   검증되지 않은 채 전제된 가정은 무엇인가
Execution    제안된 조치가 현재 인력/권한/일정으로 실제 실행 가능한가
Risk         이 결과대로 진행했을 때 실패 조건은 무엇인가
Simplicity   불필요하게 복잡하거나, 더 적은 단계로 같은 효과를 낼 수 있는가
```

## 출력 형식

ALWAYS use this exact template:

```
## Critic Review

**검토 대상:** [실행 결과 요약 1줄]

| 영역 | 발견 사항 | 심각도 |
|------|-----------|--------|
| Fact | [발견 또는 "이상 없음"] | [상/중/하] |
| Logic | [발견 또는 "이상 없음"] | [상/중/하] |
| Assumption | [검증되지 않은 가정 나열] | [상/중/하] |
| Execution | [실행 가능성 이슈] | [상/중/하] |
| Risk | [실패 조건] | [상/중/하] |
| Simplicity | [단순화 가능 지점] | [상/중/하] |

**종합 판단:** [원안 유지 권장 / 부분 수정 권장 / 재작성 권장]

---
### 다음 선택

1. 원안 유지 — 위 발견 사항을 감수하고 그대로 진행
2. Critic 전체 적용 — 위 발견 사항을 모두 반영해 재작성
3. 선택 수정 — [해당 항목만] 반영

어느 쪽으로 진행할까요?
```

## 판단 지침

심각도 "상"이 하나라도 있으면 "원안 유지"를 권장하지 않는다.
발견 사항 없이 형식적으로 6칸을 채우지 않는다 — 진짜 문제가 없으면 "이상 없음"이라고 명시한다.
Simplicity 지적은 기능 삭제가 아니라 "같은 결과를 더 적은 단계로" 관점을 유지한다.

## 사용 예시

- `방금 나온 KPI 분석 결과를 비판적으로 검토해줘`
- `이 코칭 피드백안에 근거 없는 가정이 있는지 확인해줘`
- `주간보고서 초안을 Critic Review 해줘`
